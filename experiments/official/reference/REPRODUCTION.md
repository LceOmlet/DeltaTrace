# FlashTrace — Table 1 evaluation caches & reproduction protocol

This bundle releases the exact evaluation caches behind Table 1, the underlying
1024-token RULER datasets, and the reference faithfulness/recovery result CSVs,
so Table 1 can be reproduced bit-for-bit.

Provenance: caches and result CSVs come from the original author's working
checkout at commit `075e7e4` (`exp/exp2/{data,output}/`), the final ("finish")
commit of the experiment branch. Checksums are in `SHA256SUMS`.

## Contents

| Artifact | What it is |
| --- | --- |
| `exp2_table1_caches.tar.gz` | The 13 prepared caches → `exp/exp2/data/*.jsonl`. **These fix the prompt, generated reasoning/target, `thinking_span`, `sink_span`, `indices_to_explain`, and (in `metadata`) the RULER `needle_spans`, `reference_answer`, `judge_response`.** |
| `ruler_multihop_1024.tar.gz` | The raw 1024-token RULER multihop datasets (`niah_*`, `vt_*`, `hotpotqa_long`), 500 samples/task, from which the caches were sampled. Unpack under `data/` → `data/ruler_multihop/1024/...`. |
| `exp2_table1_results.tar.gz` | The reference `faithfulness/` and `recovery/` CSVs produced by the runs below — i.e. the actual Table 1 numbers, for cross-checking your reproduction. |
| `exp2_table1_traces.tar.gz` | (Optional, ~100 MB) Per-sample attribution traces from `--save_hop_traces`: per-method attribution vectors, per-sample metrics, and per-hop token-level `V_h` with manifests. Lets you verify per-token attributions without rerunning the model. |
| `additional_experiment_data.tar.gz` | Input caches + sources for the other experiments (exp3/exp4/exp5) so they reproduce too. Unpack at repo root. See its bundled `README.md`. |
| `SHA256SUMS` | Per-file and per-tarball checksums. |

### Sample counts that enter Table 1 (per cache, after judge filtering)

All RULER tasks keep **100** judged-correct samples each:
`niah_mq_q2/q4/q8`, `niah_mv_v2/v4/v8`, `vt_h2_c3`, `vt_h4_c1`, `vt_h6_c1`, `vt_h10_c1`.

`hotpotqa_long` keeps **48** samples — these are all that passed the
generate→judge filter. (The request mentioned 66; the cache that produced
Table 1 has 48, and the result CSV directory is named `..._48_examples.csv`.)

### Cache record schema

```json
{
  "prompt":  "<context + question>",
  "target":  "<thinking text + final answer text, box wrapper removed>",
  "indices_to_explain": [start_tok, end_tok],   // == sink_span
  "sink_span":     [start_tok, end_tok],          // boxed answer span in target (token-level)
  "thinking_span": [0, sink_start-1],             // CoT span
  "attr_mask_indices": [...],                      // legacy, unused by exp2
  "metadata": {
    "needle_spans": [...],        // RULER gold spans (recovery metric)
    "reference_answer": "...",
    "judge_response": "True",
    "boxed_answer": "...",
    "outputs": [...], "answer_prefix": "...", "token_position_answer": ...,
    "length": ..., "dataset": "ruler"
  }
}
```

## Reproduction protocol (answers to the five questions)

**1. Generation / judging setup that produced the caches.**
The intermediate CoT was generated by **`qwen3-235b-a22b-2507`** (English system
prompt: "think briefly, then wrap the final answer in `\box{}` with nothing
after it"; the user prompt is the raw question, no extra template). The judge is
**`deepseek-v3-1-terminus`**, which only emits True/False on whether the boxed
answer matches the dataset reference. Token-level span detection (`sink_span` /
`thinking_span`) uses the **Qwen3-8B** tokenizer.

Note: this differs from the paper text, which says Qwen3-8B generated the
reasoning. The released caches were in fact generated by Qwen3-235B-A22B-2507;
Qwen3-8B is the *attribution target model* (the model being explained in Table 1)
and the span tokenizer, not the CoT generator.

Reproduce the sampling with:
```bash
python exp/exp2/sample_and_filter.py \
  --dataset <morehopqa | hotpotqa_long | niah_* | vt_* | path/to/validation.jsonl> \
  --max_examples 100 \
  --generator_model qwen3-235b-a22b-2507 \
  --judge_model deepseek-v3-1-terminus \
  --tokenizer_model /path/to/Qwen3-8B \
  > exp/exp2/out.log
```
Because generation goes through a sampling API, this is **not bit-reproducible**;
to reproduce Table 1 exactly, use the released caches rather than re-sampling.

**2. 1024-token context vs `auto_find_ruler()`.**
At *attribution* time the cache JSONL is passed directly as `--datasets
exp/exp2/data/<name>.jsonl`, so `auto_find_ruler()` (which searches from 4096 up,
`exp/exp2/dataset_utils.py:111`) is never invoked — the 1024 context is already
baked into the cache (`needle_spans`, prompt, spans). You only need the 1024 raw
data (this bundle) if you want to re-run `sample_and_filter.py`; in that case
point `--dataset` at `data/ruler_multihop/1024/<task>/validation.jsonl`
explicitly.

**3. `K=1` recursive hop.**
Yes. Table 1 (faithfulness) uses **`--n_hops 1`**, even though `run_exp.py`
defaults to `--n_hops 3` (`exp/exp2/run_exp.py:1144`). `--n_hops 3` is used only
for the separate `recovery_ruler` runs.

**4. Method-name → `--attr_funcs` mapping, model, settings.**
- Attribution model (Table 1): **Qwen3-8B**, `--model qwen-8B --model_path
  /path/to/Qwen/Qwen3-8B`.
- The faithfulness sweep used these attr funcs (union across runs):
  `IG`, `attention`, `attnlrp`, `ft_attnlrp`,
  `ifr_all_positions`, `ifr_multi_hop`, `ifr_multi_hop_both`,
  `ifr_multi_hop_stop_words`, `ifr_multi_hop_split_hop`,
  `perturbation_all`, `perturbation_CLP`, `perturbation_REAGENT`, and their
  `_fast` variants. `AT2` is intentionally not provided.
  (FlashTrace in Table 1 = the `ifr_multi_hop_both` / `ifr_*` family;
  the `perturbation_*` and `attnlrp`/`IG`/`attention` rows are the baselines.)
- `--num_examples 100`, `--mode faithfulness_gen`.
- Sampling order = original dataset order; `sample_and_filter.py` walks samples
  in order and keeps the first `max_examples` that pass the judge.

**5. Deterministic reconstruction.**
The caches cannot be regenerated bit-for-bit (sampling-API generation +
LLM judge). The released caches *are* the deterministic evaluation set —
download them, place at `exp/exp2/data/*.jsonl`, and the attribution stage
(`run_exp.py`) is deterministic given the same model weights.

## Exact Table 1 run command

```bash
# per task; repeat with --datasets pointing at each exp/exp2/data/<task>.jsonl
python exp/exp2/run_exp.py \
  --datasets exp/exp2/data/niah_mq_q2.jsonl \
  --attr_funcs attention,perturbation_REAGENT,ifr_all_positions,perturbation_CLP,ifr_multi_hop,ifr_multi_hop_both,attnlrp \
  --model qwen-8B \
  --model_path /path/to/Qwen/Qwen3-8B/ \
  --num_examples 100 \
  --mode faithfulness_gen \
  --n_hops 1
```
