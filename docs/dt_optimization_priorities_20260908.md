## 1. 首个质量改动：MLP 内容分支使用原输入门控

源码依据：[swiglu_finite_rule](../core/compiled_swiglu_secant.py) 的 `mu` 使用 `(silu0+silu1)/2`，`mg` 使用 `(up0+up1)/2`。PV 和注意力输出门控已采用 content_P1，不重复修改已完成的部分。

记 MLP 的上投影为 u，a=SiLU(g)。只比较现有对称分配与：

\[
\Delta(ua)=a_1\Delta u+u_0\Delta a.
\]

原因：对称规则将交互项 ΔuΔa 均分给两支；新规则将它归给内容变化，让内容分配由原输入实际门控取值决定。若 EOS 门控让无关特征获得过多分配，这会改善输入证据排序，从而有机会提高 needle、降低 RISE。MAS 同时受分配幅度和排序影响，必须实测，不能由恒等式推出提升。

该局部有限差恒等式在实数中严格成立，门控分支和负分数保留，默认 BF16/FA 精度容差不变。额外 GEMM、模型端点、整网有限传播次数均为零；可以继续复用现有编译器。数学成本不增加，但实际融合性能仍需测量。

边界：MLP 两支都来自同一个 token 的隐藏状态，内容优先不自动等于来源 token 优先；SiLU 也不是二值开关。新分配可能削弱门控/推理路由的归因，导致多跳退步。这是明确的候选假设，不能称已经更强。

验证：先冻结唯一改动，使用原 NI0 与一个已有 Morehop 开发样本，对当前 DT 和固定 FT 报告 needle/原20步 RISE/MAS及完整成本。只在一处改规则，不扫描连续权重、不按层挑选最优端点、不根据 gold 选目标。明显退步就撤回候选；样本通过只决定是否值得扩展，不构成独立确认。数值和形状守卫可先 CPU/局部验证，不能以其代替原指标。

## 2. 首个工程改动：直接复用模型的 logits_to_keep

已核对实际安装版本的原模型源码（SHA256 cf085792cb59e5bdf9b88a3d20bd353892289d054662a9c2b662221b97caefba）：`Qwen3_5ForConditionalGeneration.forward` 接受 `logits_to_keep: int | torch.Tensor`，原代码先选 hidden rows 再调用真实 `lm_head`。

当前 588 行完整 logits 只使用 248 个固定响应预测位置，即绝对位置339–586。通过官方参数直接请求这些位置，输出头行数减少57.8%；保留全部词表、真实模型 hidden states 和真实输出头，不重建 logits 或替代 softmax。该比例仅适用于输出头及其输出张量，不能当作整网加速比例。

原因：这是已定位的不必要计算；不需要新 attention、FA 适配或自写头部实现。应降低头部 GEMM、输出张量和相关搬运成本，预期不改变 needle/RISE/MAS的数学定义。

验证：同例对照已保存实际 logits/分数，比较真实目标logp、归因向量、排序/符号和原指标，允许默认内核形状变化导致普通舍入差。多样本时用目标预测位置的并集并正确 gather，不能丢目标或把 padding 当目标。若实际收益小，保留简单调用即可，不反复手写输出头融合。

## 3. 消除重复冷调用和生产路径的大量诊断 IO

证据：两个首次 decoder有限调用、seed及最终norm合计16.57秒；其余30个finite decoder合计约0.212秒。完整任务还加载模型18.29秒，诊断root/logits存档约584MB。

原因：这些是常驻模型、复用编译对象/持久缓存以及异步或按需导出可以处理的成本。优先使用现有官方 Torch 编译机制；观察 `dynamic=False` 遇到真实长度变化是否重编译，再选择有限长度桶或已有动态形状支持，不能盲目改 `dynamic=True` 并保证变快。

正常路径保留必要有限端点和分数；全账本/全 logits/全激活存档独立开关。移除重复存档不等于复用未核验缓存。首次编译和校验仍记录并摊销，不能将全部16.57秒直接扣除作为热耗时。

验证：相同输入记录首次调用和少量热调用、source/shape/cache身份、完整归因输出及峰值；不在生产计时外偷偷重算。此项目标是成本改善、质量保持，不承诺质量上升。

## 4. 真正的多样本 minibatch 和长度分桶

原因：当前一个样本占两个端点行，无法证明测试吞吐已获得多样本批处理收益。样本级B=2时真实端点B=4，才能摊薄Python调度、kernel launch和载入成本；相近长度分桶减少padding和形状编译。

使用原模型的真实mask、FA/FLA和现有有限传播批维，保留每条样本的目标offset、EOS替换范围及有符号输出。优先验证B=1→2，不盲目扩大；吞吐与显存一起报告。FLA递推在padding处的行为必须与真实模型一致，不把内部64-token tile padding误当作样本mask支持。

质量应保持；batch导致的实际数值变化直接报告。分别记单样本延迟、每样本摊销耗时、tokens/s和峰值，不把两个端点说成两个测试样本。

## 5. 有原曲线证据后，才增加条件有限传播

原因：当前 DT 分配的是所有 eligible 输入同时由 EOS 基线恢复的总效应，而 RISE 检查沿指定次序删除后的条件效应；存在交互时，端点总差守恒并不保证删除前段排序有效。后续NI0–2/MH1原曲线已重复显示静态幅度与条件删除响应失配；仍未定位到具体算子，不等于已经证明新增端点值得其成本。

触发条件：原曲线显示needle改善却在删除前段显著弱于固定FT/当前DT基线，且目标/位置无错。届时可研究一个固定中间条件的两段有限传播：I0为全eligible EOS，I1为原输入，Im为按冻结规则替换的一组输入。分解 G(I1)-G(I0)=[G(I1)-G(Im)]+[G(Im)-G(I0)]，每段仍使用同一DT规则。

中间组只能由输入/冻结候选自己的归因确定，不能使用gold、真实删除曲线或调参反馈。相比现有两个端点，会增加一个真实端点和一遍有限传播；后者成本可能接近翻倍，所以优先级低，必须先有热成本预算，不默认实施，也不声称必然改善RISE。符号依然是指定条件下的效应分配，不升级为普遍因果信用。

MAS 沿用原公式，额外记录原 signed density 和它的非单调部分；不改归一化、不将负值随意清零、不按曲线调整最终幅度以刷 MAS。只拆成正负两套分数再相加而不改变传播规则，在线性传播中不带来新信息，不作为方法创新。
