# Qwen3.5 原生 FLA 反向与上游两行修复

官方 FLA backward 已在实际 NI0 首层的 129-token 输入上跑通。最初的编译失败通过移植上游已有的两行表达式修复，未另写 backward 或改动前向公式。五类梯度与官方 CPU 参考的相对 L2 差异为 0.18%–0.79%；这支持继续接入有限传播，不证明整网归因、质量或效率目标完成。

## 故障与修复来源

第一次调用完成原生前向，在 `prepare_wy_repr_bwd_kernel` 的转置后乘法处发生 Triton `arith.mulf` 布局错误。GPU trace 证明反向状态传播等前置内核已执行，但 WY 内核与完整 backward 未完成；官方 CPU 参考尚未执行。此负结果保留。

[FLA 作者组织下的问题记录](https://github.com/fla-org/hybrid-distillation/issues/2)报告了 FLA0.4.1 同一行同一错误，但不提供对本环境的通过保证。核对[固定上游版本](https://github.com/fla-org/flash-linear-attention/blob/9d981ffef3b361ba931102b633ae2a9fd91ca6c3/fla/ops/gated_delta_rule/wy_fast.py#L217)后，只移植其“先逐元素乘、再转置”的两行表达式。原先对转置矩阵按列乘 beta，改为对原矩阵按行乘 beta 后转置；逐元素操作相同，cast、dot 和归约顺序不变。

这是明确的上游兼容改动，保留 FLA0.4.1 其余实现与实际模型默认 FA。没有整体换用新版本 API，没有把 CPU 参考或自己写的递推塞进真实模型。目标文件原 SHA256 为 `cc6c2bfdbf3b1a2c90bc0ef0c7325c53755a2a4fa440264cb39f4627d4c8de29`，修改后为 `369d3c8d88161c1b33d3d76d9cd76cdbd855d18f82ee46337fc3f0624604d1be`。

修复前后 2853 个 Transformers/FLA 文件均核验。隔离环境现有三个明确变更文件：设备名称映射、此前 state forward 流水线调度、此次 WY 两行移植；模型源码未改。两行改动前后的前向数值并非逐位相同，相对差约 0.000247%，最大绝对差 0.00003052。前向源码没有改动；没有用独立实验证明这一微差来自哪项调度变化，也不据此宣称逐位一致。

## 实际梯度与复用关系

输入来自实际 NI0 首层前 129 tokens，Q/K/V 与 beta 使用原 BF16，原始 log decay g 使用 FP32，初始状态为零。固定输出方向 Z 取自已保存的真实输出，局部检查的标量为 J=〈O,Z〉。Z 保持固定；这是局部算子检查，不能称为原解释目标上的归因、随机 VJP 质量测试或新 benchmark。

| 梯度 | 相对官方 CPU 参考的 L2 差异 |
| --- | ---: |
| Q | 0.6586% |
| K | 0.7384% |
| V | 0.7936% |
| g | 0.1777% |
| beta | 0.7517% |

五类梯度的余弦相似度均大于 0.999968，全部有限；绝对差与完整统计一并保存。没有根据本次结果追加一个“数值通过”阈值。检查仅覆盖这一真实输入、一个固定输出方向和局部零初态，不覆盖完整模型 backward、其他 batch、所有层或符号判断。

在真实 backward 中捕获到 `state_backward` 与 `wy_backward`。WY 分支返回的 dV 和原生 autograd 的 V 梯度相同；用保存的实际 A、dU、beta 在 CPU64 上逐个 64-token 块重算 beta·Aᵀ·dU，与原生 V 梯度相对差约 0.1669%。CPU 块乘法仅作核验，没有进入生产归因或模型执行。

固定路由后，V→O 为线性映射。实际原生检查中 〈V,dV〉与 J 的相对残差约 0.03710%，官方 CPU 参考为 0.00651%。它支持[有限传播契约](../qwen35_finite_extension_contract.md)中内容 V 分支的复用关系；Q/K/g/beta 的混合端点系数仍需实现，不能用普通梯度代替。

## 调用、时间、显存与捕获边界

累计两次原生 FLA 前向、两次 backward 尝试，其中一次失败、一次完成；官方 CPU 前向/反向各一次。模型加载、完整模型前向、归因、质量曲线、生成均为零。两个任务已结束。

首次本地编译与自动调优包含大量内部 kernel 调用：两个 GPU trace 分别记录 106,741 和 138,982 个 kernel events。因此“一个 API 调用”不等于一个 GPU kernel，也不能把这些调优工作漏出账本。两个诊断区间约 44.20s/66.07s，整个任务约 57.77s/98.17s；后者统计不包含最终 ZIP 打包。它们包含编译、自动调优、profile 和保存数据，不能当稳态速度或方法开销。后续复用已编译产物，并明确是否仍需自动调优。

局部 GPU 峰值约 287.10/291.31MB，不包括 9B 模型，也不代表整网归因显存。被动捕获增加约 29.05MB 的不同底层存储引用，这属于诊断接口成本。

首次被动 Python hook 没有跟随 autograd 的工作线程进入 backward，因此缺失的 Python 记录不表示 GPU backward 未执行。第二次使用公开 `torch.autograd.set_multithreading_enabled(False)` 控制该诊断调用的线程调度，真实反向算子不变；已取得完整阶段记录。这种诊断设置的计时不能当默认生产性能。

执行脚本虽然清空了捕获列表，循环变量仍可能借用阶段字典；“列表长度为零”不是 GPU 引用全部释放的证明。当前捕获器已修正为同时清空其拥有的阶段字典，并禁止跨调用重复使用同一个捕获器。弱引用生命周期检查在本地通过；这是执行后的容器管理修复，没有新增 GPU 重跑，不能冒称测得了修复后的 GPU 峰值。若调用者另行保留张量，它仍需自行释放。

## 保全与下一步

两个原始结果 SHA256 分别为 `df0fb18437ac8fce269a997f186f0a5052486edf5f28f6d66b41e59851da8d0e` 和 `b1118dd0d8ceee28fc7fff304c3d41800d718cfc6d71852e7cb65338c604515a`。第一次完整恢复包已下载；第二次下载约30.73MB精简包，包含源码、协议、七个具名输出/梯度/阶段 NPZ，以及从完整 profile 提取的 kernel 统计。所用数组逐文件哈希核对并在本地重算数值关系。第二次419MB完整 trace 和重复阶段快照留在远端完整恢复包，trace 哈希在远端再次核对，不能声称已经在本地重算该完整 trace。上游代码、MIT 许可证及版本记录随仓库保存。

这轮局部反向预算关闭，不再默认追加 backward 或精度扫描。下一步取得真实 EOS/原输入双端点，组合原生 endpoint1 状态伴随传播与 endpoint0 状态重建，实现混合局部系数，再接回整网。

官方缓存的目标 token span 和 needle gold 也需按新 tokenizer 核验。源码已确认 `attr_mask_indices` 是句子索引，必须保持原义，不能一并当作 token 索引重映射；这部分实现尚未完成。完整新模型归因、原评测质量优势、条件删除符号和成本目标继续保持未完成。
