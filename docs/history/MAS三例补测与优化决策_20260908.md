# MAS 三例补测与优化决策

2026-09-08。本轮已完成冻结的NI1、NI2、MorehopQA第1条补测，直接调用完整未修改FT e81b3be及作者原RISE/MAS。结果不支持将当前MAS差距主要解释为“样本不够，尚未测出优势”：新增三例全部退步，加上此前NI0，四例中DT的MAS均差于每一个固定FT跳数。仍然只是小规模开发结果，不代表总体显著性或所有任务。

## MAS差距具体来自哪里

DT把全EOS基线到原输入的有限总变化分配给输入token，MAS还比较这些静态分配与一系列中间删除条件。前者总和守恒，不保证每个中间集合上的分数和与实际模型效应一致。

| 样本 | 第一组分配占净贡献 | 第一组实际删除效应占净变化 | 最低DT剩余密度 | 最低原始模型响应 |
| --- | ---: | ---: | ---: | ---: |
| NI0 | 43.77% | 18.92% | −13.72% | 0% |
| NI1 | 79.49% | 72.90% | −34.84% | −6.45% |
| NI2 | 82.28% | 49.33% | −44.05% | −9.33% |
| MH1 | 51.85% | 52.94% | −16.38% | 0% |

最后两列是各自路径上的最小值，未暗示发生在同一步。MH1第一组幅度已经很接近，后续仍明显失配，因此不能概括为所有样本都只是第一组分配过大。

新NI样本确实出现了低于全EOS端点的真实负响应，不能否认负效应。问题在于DT的正负分配幅度及它们的抵消，远大于沿这条删除路径看到的变化。例如NI2的第10步，密度为−44.05%，同一步原始响应约−2.67%；并非两个指标只差一次截断。

离线去掉原模型响应的截断/单调化，DT对齐误差AUC在NI1从0.250736降至0.216543、NI2从0.349821降至0.319154；说明截断确实贡献了这两例的一部分误差。NI0则从0.172289升至0.174691，MH1从0.179690升至0.199102。不能用一个“指标不接受负数”的解释涵盖所有样本，也不能把上述离线数值冒充另一套MAS。

这些结果支持一个具体工作判断：**当前总有限差分配的幅度与删除路径上的条件效应不匹配，已跨几个样本重复出现。** 可能涉及交互项的归属、远端EOS基线引起的门控/路由变化，以及这些规则在多层中的累积。尚未定位到具体算子，不能将这些候选机制当作已证明原因，更不能由局部总差守恒宣告实现和符号全部正确。

## 执行与数值边界

新增三例均使用同一原生BF16/FA/FLA模型评分器，15条20步曲线、315次真实B1评分前向。全部FT/DT曲线的clean及全EOS输入哈希按样本一致，逐步仅替换原eligible位置。分数、排序、每组删除位置、原始评分、密度、单调响应及MAS中间项全部落盘；NumPy独立复算原指标误差低于1e-12。没有修改FT、原评分或指标函数。

输入仍使用已明确说明的外部formatter视图，以保持归因所解释的raw prompt；不能把作者评分器另加的Context/chat包装当成同一输入。本实验属于原数据和原指标在Qwen3.5上的同输入比较，不冒称论文原表完整runner复现。原评分默认精度造成的相同评分仍作未分辨的小效应，不能当作精确零。

首轮共用DT驱动从直接FA加载开始，NI0向量相对存档差3.975%，needle40%，触发预设2%控制线，在扩样前终止；保留失败，不追溯改判。检查发现其初始化/执行顺序与原成功驱动不同。另冻结恢复任务，回到原eager加载→B1诊断→官方setter切FA的顺序；NI0向量差1.886%，needle37.5%，在不放宽检查线的情况下继续完成三例。该观测支持恢复顺序后差异缩小，未证明全部差异由顺序造成。

同时修正了一处诊断命名：原root G使用实际logits的独立FP32 log-softmax，新驱动首轮却引用了编译种子内部返回的logp；恢复任务分开记录两者。只修诊断计算，有限种子及十个有限数学模块的源码哈希均不变。所有实际32层重放、8次辅助FA与同次root输出一致。输出头`logits_to_keep`优化本轮关闭，尚未验收选行收益；不把端点B2称为多样本batch。

两次任务均终止。远端执行49.70+235.98=285.67秒，另有CPU离线分析/开发/传输时间，不能混称为总墙钟时间。实际总计2次模型加载、5次DT归因（两次NI0控制）、3次完整原FT、315次评分、1次恢复顺序的原生eager B1诊断；DT共有160次实际decoder重放、160次有限decoder和40次公开FA辅助调用。没有新增生成或全数据集扩跑。不同长度、冷调用和观测开销混在本轮计时内，不作稳态DT/FT速度优劣结论。

## 下一决策

1. 停止当前扩样。四例不足以断言总体差距，但已经足以把MAS当作需要处理的方法问题，而非继续花资源等待平均优势出现。
2. 当前DT仍按用户决定作为工作版本，FT继续固定。质量改进先定位正负分配及交互归属如何产生路径幅度失配，不能只裁负、缩放最终分数或根据这些曲线挑参数。下一项候选必须说明如何改变传播中的归属，以及为何不明显增加复杂度；MLP内容优先的失败仍有效。
3. 工程路线继续复用官方输出头行选择、持久编译/模型和真正minibatch。先降低反复开发的成本；新增条件端点/第二遍传播只有明确预期和成本预算后才考虑，不因MAS落后默认翻倍计算。
