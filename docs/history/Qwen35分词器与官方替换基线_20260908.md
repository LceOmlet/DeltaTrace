# Qwen3.5 分词器与官方替换基线

共享权重的六个 tokenizer/config 文件均匹配固定官方版本，真实 AutoTokenizer 已加载，官方缓存 NI0 与 MH1 的原 prompt/target 分别编码解码后文本完全一致。没有加载模型、生成回答或运行删除评测。完整聊天输入组装、目标边界、gold 重映射、GPU FLA 和整网归因仍待实现。

发现并纠正了此前过严的检查：tokenizer EOS 不必等于模型 config EOS，tokenizer 大小也不必等于 embedding 容量。此处实际为：

| 官方字段 | 值 | 接入含义 |
|---|---|---|
| tokenizer EOS | `<|im_end|>`，248046 | 作者实验入口将 PAD 设为此 EOS |
| tokenizer 默认 PAD | `<|endoftext|>`，248044 | 不能直接当作作者实验最终使用的替换 token |
| model config EOS | 248044 | 与 tokenizer EOS 不同；保留官方配置 |
| tokenizer 长度 / 最大 ID | 248077 / 248076 | 均在 embedding 有效范围内 |
| model embedding / 输出词表容量 | 248320 | 不能按 tokenizer 长度裁掉 softmax 类别 |

已重新读取并核对原作者 `exp/exp2/run_exp.py` 和 `llm_attr_eval.py` 的固定源码：前者第 821 行将 `tokenizer.pad_token = tokenizer.eos_token`，后者第 86—91 行读取 PAD 作为基线。因此新模型沿用该实验处理后应使用 **248046** 做删除替换，而不是仅从模型 config 取 248044。此结论来自实际调用链，不修改官方模型文件，不声称“EOS 是哪个”只有一个全局答案。模型生成终止配置与已冻结回答的删除替换是不同用途，本阶段不生成新回答。

官方来源为 [Qwen3.5-9B 固定版本](https://huggingface.co/Qwen/Qwen3.5-9B/tree/c202236235762e1c871ad0ccb60c8ee5ba337b9a)。检查覆盖 `tokenizer.json`、`tokenizer_config.json`、`chat_template.jinja`、`merges.txt`、`vocab.json` 和 `config.json`；LFS 文件核对 SHA256，其余文件核对大小与 Git blob SHA1，同时记录本地 SHA256。官方 API 元数据原件 SHA256 为 `ef909fe5b1e01dd51381f3ed429395a0ec6a24822d61fbbeaad0adb0ca4cfa5b`。
