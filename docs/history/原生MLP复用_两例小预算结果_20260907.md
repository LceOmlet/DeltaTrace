# 原生 MLP 复用与剩余优化空间

本轮实现了 PyTorch 公开选择性激活检查点（SAC）的 MLP 复用，并完成两个原开发样本、总计 12 次归因的小预算初筛。模型、默认 FA 和有限 P1 数学规则保持原样；没有新生成、FT 扫描或删除曲线。研究尚未完成。

## FA 已覆盖什么，还剩什么

|过程|当前实现与剩余空间|
|---|---|
|真实模型注意力|使用默认厂商 FA；未复制模型注意力或反向。|
|双端点有限注意力|复用可追溯 FA 框架，三遍分块传播，避免全局 N×N 张量；仍为三个 kernel，不能把它说成一次默认 FA 反向。进一步合并须先解决行归一化依赖。|
|原生层重算和线性投影|仍有真实 GEMM；FA 不覆盖 MLP、输出头或整网有限传播的线性投影。本轮用公开 SAC 复用同端点已有 MLP 输出。|
|RMSNorm、残差、SwiGLU、布局与种子计算|部分已有 torch.compile 融合，整条链尚未融合。可继续减少独立逐元素运算、临时张量和启动开销。|
|数值与来源检查|仍有逐层比较、归约和 GPU→CPU 同步。可以研究合并检查、延后读取结果，保留校验含义。|
|语言模型输出头|当前根前向计算全部位置 logits，再丢弃无用位置。优先使用模型原生 logits_to_keep，仅保留固定目标的预测位置；每个保留位置仍需全部词表用于 log-softmax。尚未实现此项。|
|额外 FA 元数据调用|每层仍有一次公开 FA 调用取得文档支持的 LSE。先不为消除它改用私有返回值或复制注意力。|

既有 NI0 trace 中，真实 FA 占 GPU kernel 累计时长约 1.9%，有限 FA 扩展约 12.1%，全部 GEMM 约 50.4%，其他 kernel 约 35.5%。这是一个较短开发样本的 GPU 时长组成，**不是端到端耗时占比，也不能直接据此承诺加速比例**。证据：`existing_finite_profile_reuse_analysis_20260907.json`。

## 新实现与实际结果

使用安装版 `torch.utils.checkpoint.create_selective_checkpoint_contexts`，每个原生 MLP 一个独立缓存区域，只保存其真实 gate/up/down 三个 `aten.mm` 输出。既有同端点重放调用仍经过原生 MLP；PyTorch 自身管理缓存与版本检查。缓存限定在一次归因，消费后释放，不跨干预或样本复用。源码记录 PyTorch 检查点实现哈希；没有复制 dispatcher、GEMM、模型或 FA。

|原开发样本|原有限 P1 耗时|缓存末 32 层耗时|峰值显存变化（十进制 GB）|
|---|---:|---:|---:|
|NI q2，第 2 条，N=1241|0.9889 s|0.9124 s，下降 7.7%|18.760 → 23.880，增加 5.120|
|MoreHopQA，第 5 条，N=355|0.4526 s|0.4416 s，下降 2.4%|17.323 → 18.812，增加 1.489|

NI 为两次稳态测量的中位数；MH 只有一次稳态配对，不能认定其小幅变化稳定。预热和编译时间另行保留，不混入上述比较。候选实际 trace 为 663 个 GEMM kernel、108 个原生 FA kernel、108 个有限 FA kernel；32 个 MLP 的 96 个 GEMM 输出被真实复用。注意力调用没有减少。

所有本次新旧配对的完整带符号向量、投影分数和端点分数完全相同，符号翻转为零。但是，本次新旧两路都与较早质量实验的分数略有差异，原因未确定；因此**没有继承旧 RISE/MAS 曲线，也没有新的质量结论**。两例同次等价不能代替跨环境、长输入或 B4 验证。

全 36 层版本先执行 2 次归因，按当时固定显存门槛停止，未取得可比较的稳态耗时。随后仅将缓存减为末 32 层，执行余下 10 次。完整失败与调整证据保留，合计 12 次；不把预热 19 秒对 1 秒冒充加速。两个远端作业均已结束。

## 用户更新后的显存标准

用户随后明确：显存上下浮动按 FA 参照判断，不应定死为不能更高。**取消“一次原生反向 + 72.5 MB”的固定准入线**。相同模型、设备、FA 后端、dtype、长度和实际 batch 下，分别报告归因、真实 FA 前向/同目标输入反向的峰值与耗时；比较额外显存换来的延迟、吞吐收益及最大可运行长度/batch。保持避免全局 N×N 归因存储的目标，不把固定字节或比例另设为新硬线。

原始协议、原始结果及核验中的旧 memory gate 是当时执行事实，不能回写。按新标准，全层缓存恢复为可研究候选，速度仍未测定；末 32 层版本是有小范围收益证据的可选原型，尚非所有形状的默认配置。当前增加约 5.12 GB 换取 NI 单例 7.7% 耗时下降，是否值得要结合吞吐与容量判断。

下一优先级是原生 `logits_to_keep` 和已有编译器减少小算子/同步；缓存作为可调的计算与显存取舍保留。该输出头优化也应公平核对原 FT 路径能否省去无关计算。没有足够证据时不重跑全表、不扫描缓存层数寻找漂亮数字。

## 固定比较口径，避免再混淆

- **FA 有限 P1 对显式有限 P1**：原 16 例耗时中位数下降约 11.2%。这是有限实现之间的比较。
- **P1 对 FT**：作者总 API 会额外计算未使用的 row/rec 视图。省去这些、保留作者原 seq 分数后，FT 耗时约降 30.4%，P1 在该同次 16 例比较中反而慢约 37.7%。本轮两例缓存初筛没有重新测 FT，不能据此更新这个差距。
- **FT 两条代码路径**：`legacy` 是本项目对作者 `calculate_ifr_multi_hop` 的标签；`both` 是作者 `calculate_ifr_multi_hop_both`。二者主要区别在答案/推理 token 的传播范围；0–3 是额外信用传播跳数，0 也包含完整基础归因，不是零计算、网络深度或重新生成。
- 作者[官方缓存发布说明](https://github.com/wbopan/flashtrace/releases/tag/table1-data-v1)明确：Table 1 忠实度使用 K=1，恢复实验使用 K=3。历史各指标最强的固定配置不相同：NI RISE 为 legacy0、NI 恢复为 both0、MH RISE 为 both2，不能拼成一个统一方法。
- 历史 NI 的 P1 RISE 为 0.05736，固定 legacy0 为 0.06193，越低越好。此前“RISE 更差”涉及看完每例结果后选择最优 FT 变体的 oracle、以及旧总入口预算；它不是可部署的固定 FT 基线。更早 SYM→P1 的 NI RISE 为 0.064765→0.057423，并非下降为更差。

官方发布说明也明确生成器与裁判来源，不能仅以“脚本默认值不证明历史”否认其作者记录。当前使用作者处理后缓存，无需重新调用生成器/裁判；原 8 条开发均值不是整张论文表格复现。
