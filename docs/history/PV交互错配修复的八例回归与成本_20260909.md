# PV 交互错配修复的八例回归与成本

本轮确认了一处有实际证据的归因机制问题：在 Qwen3.5-9B 的 MH0 第19层，有限注意力传播用 EOS 端点内容解释部分删除后的路由变化，产生了很大的条件误差。只在这一层改用 P0 内容分配，复用原有限 FA 后端，明显改善了 MH0 的完整归因和原 MAS；固定8例中 MAS 共6例改善、2例退步。

这仍只是局部修复。原 RISE 有6例退步，NI 的 needle 总恢复数从105/154降到103/154；MoreHopQA 的 MAS 均值仍差于历史固定 FT3。双删除背景审计进一步表明，候选在已测固定状态上的幅度预测更准确，并不保证它据此选出的删除排序更好。同形状热计时和峰值显存基本保持，但质量上的取舍尚未解决。**Goal 继续 active，不把 PV19 升为默认配置，也不宣称已打过 FlashTrace。**

## 比较对象与原基准范围

C 是本轮开始前的当前 DT：第0层采用对称 normgate 和完整有限 FLA 端点顺序平均，8个全注意力层仍用 content-P1。P0 是唯一候选：只令第19层使用 content-P0，其余层及上述第0层修法不变。第19层是根据 MH0 实际误差定位选择的开发改动，不是预先证明适用于所有层的规则。

质量测试固定使用作者处理好的 NIAH q2 0–3、MoreHopQA 0–3。没有新生成、换样本、改 gold 或自造基准。原 prompt 后接原 target 与 EOS；用作者函数重映射当前 tokenizer 的 span/gold。每种方法均以自己新生成的带符号归因、自己的20组删除集合运行原 RISE/MAS；负数不裁掉，最终分数不校准。RISE、MAS 越低越好，needle 越高越好。数据已在开发中使用，不是独立 heldout，也不是论文完整表格的复现。

FT 固定在 e81b3be50a48dcfc652fbf1b530069b552736e66。此前完整原 Both 流程保存了 FT0–3，并实际评分 FT0 和 FT3；本轮引用该原8例中的 FT3，未重复运行或修改 FT。FT 内部解释作者的 sink representation，DT 内部解释整段固定回答加 EOS 的 logprob；共同输入、回答与原评分目标一致，不意味着内部种子完全相同。

用户指出的 MH0 **DT MAS 0.403351 对 FT0 0.293223** 是真实的同例劣势，不能用别的 MH1 结果替代。那是先前单例进程的结果；本轮同进程 C/P0 对照从 **0.391213** 开始，不能拿0.403351当作本轮 C 来放大改善。先前跨进程发现过约2.262%的 DT 向量差异，原生目标及 FT 向量也有变化；尚无证据把它简单归为无害舍入。本轮 C/P0 的原生端点与相同输入评分一致，主结论依靠该配对比较。历史 FT 只作带来源的描述性对照；MH2 的历史全 EOS 原评分与本轮还相差2 logprob，其余案例端点相同也不能保证中间轨迹无漂移。

## 从实际边界到可修的 PV 规则

此前第0层修复已并入 C，MH0 的剩余问题不能再笼统归给 FLA 或负质量总量。实际粗边界先显示第19层是 early、middle 的大头，再用真实保存的层输入、原生调用参数与上游系数重放该层。以下统一采用“预测−实际”：正值是删除效应的过预测，不是负向因果贡献。

| MH0 第19层实际账本 | step3 | step10 |
|---|---:|---:|
| 有限 FA 核心，含既有 seed BF16 cast | +15.003021 | +18.072608 |
| decoder 全部项净值 | +10.599711 | +11.904296 |

输入/输出重放与保存系数的迁移项为0。其他 norm、gate、MLP 项有负向补偿，不能把各项绝对值同时压小当作修好。接下来的11次默认公共 FA 算子对照，在不物化全局概率矩阵的条件下，把完整 core 分为：

| core 误差来源 | step3 | step10 |
|---|---:|---:|
| EOS 内容下的路由预测误差 | +6.702619 | +7.863335 |
| 原输入路由下的内容预测误差 | +0.079080 | +0.029794 |
| EOS 参考内容与实际保留内容的路由交互错配 | +8.221321 | +10.179479 |
| 合计 | +15.003021 | +18.072608 |

令 C/A 为实际 clean/部分删除状态，V0 为原 EOS 端点内容，m 为真实上游。第三项理想形式是
\[
\langle m,(P_C-P_A)(V_0-V_A)\rangle.
\]
同一路由变化按 V0 收缩为 +1.994513/+4.277872，按实际 VA 收缩却为 −6.226808/−5.901607，方向发生反转。实际输出重放完全相同，seed 转换影响仅约 +0.002111/−0.001766，无法解释这个量级。混合 Q/K/V 调用只是算子对照，不是完整模型反事实，也不能把 query 位置当作证据来源 token。

剩余路由项又用原可追溯分块诊断拆开：

| EOS 内容下的路由误差 | step3 | step10 |
|---|---:|---:|
| QK 交互及乘子舍入 | −0.332014 | +0.073075 |
| tile 权重 BF16 转换 | +0.000360 | −0.001630 |
| 固定端点 softmax 对实际删除方向的条件项，含原精度边界 | +7.034273 | +7.791889 |

系数与原生重放差均为0。这定位的是**归因有限规则对非原端点方向的失配**，没有证据表明官方 FA 前向算错。PV 参考内容与 softmax 条件项都是已测大头；不能把前者修复后仍剩的误差忽略掉。

记0/1为 EOS/原输入端点。原 P1 与候选 P0 满足：
\[
\Delta(PV)=\Delta P\,V_0+P_1\Delta V
          =\Delta P\,V_1+P_0\Delta V.
\]
P0 把双线性交互归给路由分支，路由用真实原输入内容 V1，内容变化按 P0 分配。两式端点守恒相同，但部分删除状态 A 不在这条弦上时，分配结果可以不同；没有“P0 总是更忠实”的保证。

当前 logmean softmax 有限算子、QK 中点对端点交换对称，所以只交换有限后端的 q/k/LSE 两端，并让 v0 槽读取真实 v1，就得到 P0 系数，不取负号；门控、投影及输入边界保持原端点次序。仍是同一个已验证原库、一次三阶段核心，既无新 GEMM，也无两次 FA 后平均的生产成本。归因扩展复用可追溯 vendor FA 的分块和 GEMM 框架；模型的默认 FA、FLA 及官方 FT 完全未改。这个交换技巧只适用于当前端点对称后端：未来若换成非对称 clean-Jacobian/supported-secant，交换还会改变 Jacobian 的参考端，不能直接当通用 PV 开关。

局部同源试验中，新 control 的 dq/dk/dv 与原保存系数逐位相同。P0 将 core early 15.003021降到−0.350040，middle 18.072608降到4.9589；对称平均代理只降到7.3265/11.5158。全 EOS 条件误差0.0735→0.1556、原 B2 弦残差0.0244→0.0316，均保留，不把近似守恒当质量证明。正因它同时改善两个主要条件方向且不增加核心次数，才推进完整输入测试。

这项改善来自两支的联合重分配：early/middle 的 QK 预测分别增加17.894/25.671，V 预测分别减少33.247/38.785，合计才得到较小的 core 误差。不能把参考内容项减小解释为路由分支已经独立修好；新 core 的正负 token 残差仍会抵消，完整账本保留这些分量。

旧 Qwen3 的16例开发试验曾显示：全网 P0 相比 P1 的 NI needle 低约4.85个百分点。这是反对直接全层替换的既有反证，不能被本次局部结果抹掉。这里检验的是当前 Qwen3.5 的单层开发候选。

## 双删除背景交叉：幅度改善与排序代价并存

只检查 C 选择的删除集合存在选择背景。为避免这个误导，使用两方法已经保存的全部曲线和向量，做了零新增评分的2×2交叉：
\[
E_{a,b,t}=\sum_{i\in A_{b,t}}s_a(i)
 -[G_b(\varnothing)-G_b(A_{b,t})],\quad a,b\in\{C,P0\}.
\]
每个背景 b 都用它自身真实的评分。主计算对实际评估 FP32 分数用 CPU FP64 求和；完整 FP64 向量复核最大差不足9.1×10⁻⁷。同一输入跨两条曲线的评分差全部为0。MAE_AUC 是原21步轴上的绝对 logprob 预测误差积分，不是原 MAS。

| 案例 | C 删除背景：C→P0 MAE_AUC | P0 删除背景：C→P0 MAE_AUC | 自身路径：C→P0 MAE_AUC |
|---|---:|---:|---:|
| NI0 | 16.097→14.650 | 17.746→16.868 | 16.097→16.868 |
| NI1 | 10.894→9.049 | 11.776→10.709 | 10.894→10.709 |
| NI2 | 17.169→14.774 | 15.090→14.319 | 17.169→14.319 |
| NI3 | 19.661→17.812 | 22.482→21.444 | 19.661→21.444 |
| MH0 | 32.263→25.282 | 28.706→23.388 | 32.263→23.388 |
| MH1 | 9.669→8.533 | 10.509→9.875 | 9.669→9.875 |
| MH2 | 36.252→34.350 | 35.191→34.321 | 36.252→34.321 |
| MH3 | 25.721→20.287 | 27.092→23.573 | 25.721→23.573 |

8例在两种固定背景上都得到更小的误差积分，但 C 背景的152个内点仍有4个退步，P0 背景有13个，不能用积分隐去局部错误。更关键的是，自身路径在 NI0、MH1、NI3 上分别增加0.7712、0.2054、1.7826：改变排序后所选实际状态的差异，抵消了固定状态上的幅度收益。

以 NI0 为例，自身 MAE 变化可写成固定 P0 背景上的系数改善−0.8780，加固定 C 系数时的背景变化+1.6492。反向分解也完整保存。这是观测量的代数分解，不是唯一因果分摊。证据不支持“P0 在自己选择的新状态上系数整体都更差”，同样不支持“条件幅度已普遍修好”：只覆盖两族由方法选择的状态，不能外推任意删除集合。

RISE 直接评价实际删除路径；MAS 另受有符号 density、归一化和作者后处理影响。NI3 自身 MAE 增大但 MAS 改善，说明不能把二者混称一项。原 MAS 的负 density 惩罚项下降对均值改善有贡献，但这不等于负归因本身错误，也不是裁负的理由。

NI0 的原 top10%预算为31个 token、eligible gold 为40个，恢复16→15。gold 91、137分别由名次31→40、28→34退出，gold 83由34→27进入。两边阈值都唯一，没有 top-K tie 歧义；这里只核分数和位置，未解码文本。该实际排序损失需要解释，不能用 needle 理论预算上限或小数值波动略过。

## 成本与真实批处理

新的成本任务针对**同一形状下 C 对 P0**，每种形状先各预热一次，再 C/P0/P0/C 测量。单样本是 NI1；真实双样本是原记录 NI1+NI46，每条均为1201 token，但输入/回答不同，实际物理端点顺序为 baseline1、input1、baseline46、input46，返回两条独立归因。它不是复制同一样本，也不是把 EOS/input 两行冒称双样本。

| 本轮同形状热测量 | C 中位数 | P0 中位数 | P0−C | C/P0 峰值 allocated |
|---|---:|---:|---:|---:|
| NI1 singleton | 1.292187 秒 | 1.308787 秒 | +1.2846% | 均20,496,067,072 bytes |
| NI1+NI46 true batch2 | 2.275079 秒 | 2.272540 秒 | −0.1116% | 均22,101,504,000 bytes |

同形状峰值差为0；没有增加核心调用次数或平方阶存储。计时保留原生 head、CPU checkpoints、端点复制、FA/FLA/conv、公共 LSE 和第0层平均；预热与加载另列，不用首调用8.44秒假装 control 很慢。每方法每形状只有两次热观察，不能把约0.1%的差异称为提速，也不能据此给所有长度设显存上限。

同形状同方法的预热/热测完整向量与目标 logprob 均逐位重复一致；同形状 C/P0 原生目标一致。NI1 在所有模式下为37/38，NI46 在真实 batch 中两方法也为37/38。NI1 跨形状的完整向量相对 L2 差为 C 1.9715%、P0 1.8776%，原生目标差亦保留；只有3/21个删除输入相同。**本次成本任务没有评分，不能宣称 P0 的 batch RISE/MAS 已通过。** NI46 没有本轮 singleton 对照，也没有交换样本行测试；这不是任意 batch 隔离的证明，异长数据仍未验证。

旧 C profile 的真实 batch 结果必须另列：此前在两次 singleton 合计与同两样本 batch 间，2.671082→2.288799秒，观测吞吐增加16.70%、峰值增加约1.50 GiB。其后用保存向量另跑的原曲线如下；这些不是 P0 的新批处理质量结果：

| 旧 C profile | RISE：singleton→batch向量 | MAS：singleton→batch向量 | needle |
|---|---:|---:|---:|
| NI1 | 0.03790323→0.03919355 | 0.16255650→0.16379100 | 37/38不变 |
| NI46 | 0.04983660→0.04428105 | 0.21443221→0.20316193 | 37/38不变 |

旧 NI1 仍有退步；旧 NI46 的改善不能替代新 P0 的验证，也不能用本轮 NI1 singleton 去估计两个不同 singleton 的合计速度。旧试验还保存了 NI46 的 batch 端点残差约+0.63654、singleton 约−0.00696；这一数值边界没有被 needle 不变掩盖，亦未靠修改原生框架消除。

本轮8例质量任务用了16次完整 DT、400次有限 FLA/800个原生伴随阶段、128次有限 FA和128次公共 LSE、512次原生层重放、336次原评分，墙钟294.962933秒。新成本任务用了12次 DT、300次有限 FLA/600个伴随阶段、96次有限 FA和96次 LSE、384次层重放，零评分，墙钟86.494466秒。两部分共381.457399秒，均无 FT、生成或新 FA 编译；前述局部诊断、旧 batch 作业及历史 FT 是各自独立成本，不冒充正常单次归因延迟。2×2交叉只是保存数据的 CPU 审计，没有增加那336次评分。

本阶段发布的13个已终止作业，合计墙钟670.329061秒，包含旧 batch 成本/质量、MH0 各级诊断、失败检查回执、本轮8例回归及新成本测试。失败证据保留在总账中；这个研究阶段总成本与上述单次热归因延迟含义不同。

## 当前判断与下一步依据

PV19 修复有三层实际支撑：真实算子对照定位了参考内容错配；同原库的局部 P0 完整 core 改善；完整8例及双背景测试证实了有限范围内的幅度和 MAS 收益。与此同时，排序代价已经由原 RISE、needle 和两个背景上的自身路径误差明确暴露，不能只保留 MH0 的正结果。

当前默认继续用 C。后续优先解释已保存 NI0/NI3 的 gold 换位以及 MH1 的排序路径损失，并把两类删除背景都纳入判断；不能只优化 C 选出的集合、全层套用 P0、裁负或调最终幅度。MH2 对历史 FT3 的 MAS 差距和仍然很大的条件误差尚未解决。任何后续方法都需保持原 needle/RISE/MAS 回归与实际成本检查，8个已用案例也不能代替更广泛验证。

原 Euclidean 全8层 softmax 修正曾在 NI1 的整网 MAS 0.196942→0.252133上真实退步，可否决当时的具体版本；同次 MH1 有改善，不能由此否定一切 softmax 改法。概率支持的 supported-secant 只完成过旧 MH1 单层测试，其整网两例载荷虽已冻结并保留当时21文件的完整旧 API 源快照，**本轮没有运行**。不得把准备文件当作结果，也不得因它尚未测过就越过当前证据自动启动。当前 PV 端点交换和非对称 softmax 后端的组合也尚未定义、验证。

完整向量、两套删除输入、负值、原曲线、源码指纹、成功与失败回执均保留。数值接近守恒只验证账本，不验证单个 token 的方向；吞吐接近也不代替方法质量。研究目标仍未完成。
