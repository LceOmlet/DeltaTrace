# FA 阶段剖析与 B4 原生 MLP 复用

当前结论：保留共享均值版有限 FA，开始按实测成本处理重复 GEMM。公开 PyTorch SAC 的 B4 小试完整向量与端点相同，唯一一次计时配对约快 10.3%，但峰值显存增加 9.67 GB；仅保留为可选实验实现，不升级默认，也不扩大这轮 GPU 测试。没有新的 FT、质量或符号胜出结论。

## 为什么现在可以转向其他主要耗时

对相同 NI0 第 35 层真实端点，固定源码和已编译库，进行了 4 次局部算子调用：两次预热、两种实现各一次剖析。没有整网归因、生成或删除评测。原三次扫描的 Q/KV 传播分别为 465.920 / 545.536 μs；两次扫描版合并传播为 1594.624 μs，约高 57.7%。其线性 Q 转换只有 13.568 μs，占新实现 GPU 内核累计时间的 0.67%。因此当前退化集中在合并传播内部，继续只优化线性转换不值得优先投入。

这一剖析不能进一步分离原子操作、寄存器溢出和转置各自的代价，也不是新的普通计时。此前无 profiler 的局部 1.87→2.44 ms、约慢 30.5% 仍是单独证据。新旧 Q 相对 L2 差约 1.21e-6、无反号；K/V/tau/center 相同，保持 FA 默认精度政策。

同时对已有共享均值版的真实 B4 预热 trace 重做了 CPU 分解，未增加 GPU 调用：命名的厂商 GEMM 占 GPU 内核累计时间 51.38%，有限 FA 占 10.98%，默认模型 FA 占 2.17%，其他占 35.47%。这包括预热可能触发的编译工作，不能当作稳定整网时间占比或严格的加速上界；但连同现有 B1 原生 MLP 复用结果，足以支持一次小预算 B4 接线检查。没有证据表明所有 FA 优化空间已耗尽，尤其不能外推到长序列。

发现并记录了旧两次扫描协议的元数据错误：`pass_count=3` 和三阶段共享内存字段来自旧协议，未随最终内核更新。实际固定源码是两次平方扫描加一次线性转换，共三次发射；合并阶段共享内存为 18 KiB。历史原件及其哈希保留，新解释不再使用这些过期字段。执行源码、库及数值原始证据未被替换。

## B4 修改是什么

保持原生模型 FA 和当前 `VendorFAFiniteP1SharedMeanReuse`。只通过安装环境中的公开 `torch.utils.checkpoint.create_selective_checkpoint_contexts` 复用最后 32 层 MLP 在真实端点前向中产生的 gate/up/down 三个矩阵乘输出。重放前核对真实输入、权重版本及运算描述，每次归因独立缓存，用完释放；没有替换模型 forward、FA 或梯度实现。

修正后的缓存上下文在完整计时上下文内创建和退出，安装前和清理后仍必须没有遗留钩子。计时包括输入准备、端点捕获、传播、缓存安装/清理及同步。复用是显式的重算优化，不冒充新的模型调用。有限传播公式及符号含义不变。

选择固定为官方已处理缓存的 NI0、NI3、NI6 和 MH1，真实样本 batch=4，双端点物理 batch=8，padding 后长度 607；没有新生成、gold 调整、质量曲线或参数搜索。

| 同次、非预热的唯一计时配对 | 当前共享均值 FA | 加原生 MLP SAC |
|---|---:|---:|
| 完整耗时 | 1.506934 s | 1.352120 s |
| 峰值 allocated 显存，十进制 GB | 21.6990 | 31.3664 |
| 完整有符号向量及端点分数 | 与候选相同 | 与基线相同 |

候选约快 10.27%，峰值增加 9.6674 GB（约 44.6%），每次实际最大保留缓存 10.1838 GB。两次候选调用均保存并复用了 96 个真实 mm 输出；预热 profiler 记录厂商 GEMM 为 663 次，对应既有相同 B4 预热 trace 的 759 次，少 96 次。默认 FA 和有限 FA 内核各仍为 108 次，未把减少 GEMM 说成减少模型端点或 FA 调用。

只有一次正式配对，不能宣称稳定提速。额外缓存随 batch 和长度线性增加，可能减少可运行的 batch，不能由此声称吞吐或长序列更好。此前相对公平 FT seq 入口慢 37.7% 的结果没有在本次重测，禁止用跨作业百分比相乘推导新的 FT 差距。当前向量相等也不能自动继承不同父版本的旧 RISE/MAS 曲线，更不证明符号对应条件删除方向。

## 失败与全部预算

保留两次接线失败，修正没有放宽检查：

1. v1 全局 `extension` 仍绑定旧非 compact-GQA 包装器，在形状检查处停止。执行了一个部分根前向归因调用、一次层重放和一次辅助 FA；未发射有限算子，未得到完整归因。
2. v2 完成了一个基线预热，随后候选在 `measured()` 入口因过早安装 SAC 钩子被拒绝，尚未运行模型。`finally` 使用未赋值的 `cost` 又掩盖了原始异常，两层错误均保留。
3. v3 将 SAC 生命周期移入计时上下文，保留零钩子检查，并预置失败记账及原始异常记录。只用剩余三次：候选预热、基线计时、候选计时；全部完成。

三作业合计 6 次 API 尝试、5 次实际根前向、4 次完整 B4 归因（其中两次预热）、145 次层重放、145 次辅助 FA、144 次有限算子调用（432 个有限内核发射）。零 FT 调用、零 VJP、零新删除曲线和零生成。三个脚本内部任务时长合计约 165.01 秒；这不包含启动前准备和退出时打包、传输，不能当作整个研究过程总用时。局部 FA 的四次算子调用另计。

所有作业已终止，原始结果、源码、协议及 profiler 证据已收回；本轮不重新开启或扩大 GPU 测试。

## 连贯的下一步

默认保持现有共享均值有限 FA，保留 SAC 为资源充足时的待确认选项。本次证明减少真实 MLP 重算确实可带来收益；没有理由为一个约 10% 的单次收益默认增加约 45% 峰值。后续成本优化优先寻找无需跨层长期保留大激活的开销，先用已有 trace 定位，不继续搜索缓存层数。

继续 Qwen3.5-9B 的真实后端接入：已验证共享权重与真实 FLA 导入，下一步先核对官方 tokenizer，并准备官方固定文本的重新分词及实际原生 FLA GPU 预检。不能把 import 成功当 GPU 分派证明，也不能把 Qwen3-8B 的 FP16/D128 有限算子直接套到新模型 BF16/D256 或门控状态更新。新模型完整归因、真实批处理与质量验证仍未完成；不生成替代官方轨迹。
