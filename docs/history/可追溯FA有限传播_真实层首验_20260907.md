# 可追溯 FA 有限传播扩展：首个真实层验证

已按用户最新边界实现首版：默认模型 FA 保持原样，独立命名的有限传播扩展复用可追溯 FA 框架，主要消除归因的平方级中间存储。首个真实层的数值、运行轨迹及局部成本已核验；尚未接入整网，不能继承原 P1 的基准成绩，也不能称为默认 FA 同速。

## 实现与来源

扩展为 `vendor_fa_finite_p1.cu`，复用 MetaX 官方 mcXformer 提交 `aef88de756194e077460a1c8b8b341baa429259a` 的 FA2.5.3 框架。78 个上游文件按原字节保存，保留许可证。使用其 `Flash_fwd_kernel_traits`、分块拷贝、`flash::gemm/gemm_rs`、MMA 累加布局、半精度转换与行归约。编译前后上游哈希一致；本项目只新增明确命名的有限算子和张量入口，没有覆盖安装包、注册替代 autograd 或替换模型前向。

实际模型仍使用已安装 FA2.6.3 厂商版本。2.5.3 源码不是该二进制的精确对应源码，本扩展也不冒称其官方标准 backward。自己的有限传播库独立编译，通过公开张量及设备流调用，不依赖安装 FA 的私有返回槽或参数结构。模型 FA 升级不要求同步改写有限规则；仍有设备编译器和所固定框架的兼容维护责任，不能承诺所有未来版本零验证。

数学规则保留内容 P1：`Δ(PV)=ΔP·V0+P1·ΔV`。令 `L=logmean(P0,P1)`、`T=U·V0ᵀ`、`c=Σ(LT)/ΣL`，传播 `DS=L(T−c)`，再求 Q/K/V 的有限乘子。分三遍：行统计、Q 乘子、K/V 乘子。没有积分近似、没有把普通梯度换名。

精度为 FP16 矩阵乘操作数、FP32 累加/指数/行归约、FP16 Q/K/V 输出；上游 U 和端点均值的转换完整计费。概率归一化使用实际公开 FA LSE，与旧显式 FP32 再归一化存在浮点差异，已纳入误差比较。不是与默认 FA 相同的数学问题，不能以“默认精度”直接保证误差相同。

## 针对什么内存

旧路径显式构造 `[B,H,N,N]` 的分数、概率、logmean 和乘子。这里的 N 是提示加固定 rollout 的总长度。本扩展只持有 `[B,H,N,128]` 操作数/输出、`[B,H,N]` 行统计及每个块固定 16 KiB 共享内存；没有全局 N×N 缓冲区。

因此，固定 head 数和维度后，此注意力有限算子的额外存储随 N 线性增长；计算仍为 O(BHN²D)，三遍带来常数开销。这不是线性时间算法，也不保证整网峰值同样下降：原生产路径尚有显式审计矩阵，接入时必须一起移除其运行时物化，不能只替换最后的矩阵乘。

## 实际数据与完整局部输出

只使用 FlashTrace 原 NI0 样本的真实第35层：B1、H32、N601、D128，原生 GQA 组数4。端点来自未修改的 Qwen/FA，U 与旧有限乘子来自实际 P1 传播。没有新增质量基准或人工随机输入。旧最小显式控制和独立 CPU64 公式都比较完整数组。

|局部操作|三次实测耗时中位数|额外峰值|
|---|---:|---:|
|最小显式 P1 控制|7.119 ms|524.52 MB|
|新 FA 框架有限传播，含包装转换与分配|2.106 ms|64.00 MB|
|默认原生 GQA FA 前向+反向参照|0.827 ms|45.25 MB|

新扩展相对显式控制提速3.38倍、额外显存下降87.8%；仍为默认 FA 前向+反向的2.55倍耗时。默认反向是成本参照，不是有限传播的数学答案。显式控制使用所需 P1 公式和 eager logarithmic mean，不能把这张局部表当作完整生产方法速度对比。计时包含真实包装与转换，排除计时后的 CPU 保存和诊断；每种方法一次预热、三次交错实测，另有两次 profile。冷启动也保留在摘要。

Q/K/V 完整乘子对捕获旧结果的相对 L2 误差分别为0.0431%、0.0424%、0.0330%；通过事前1%的局部筛查，独立 CPU64 检查一致。该阈值只用于局部开发，不能代替整网或原基准验收。有限输出各次重复一致；普通 FA 梯度重复不逐位一致，未对其声称逐位稳定。

FP16 存在小值归零与反号：Q/K/V 的非零反号分别2688/160/4个，其对应参考 L2 占比分别约2.37e−6、6.24e−7、4.31e−8；非零变零分别72354/16521/32845个。没有负值裁剪。这是内部乘子统计，不能直接当作 token 方向正确性。局部有限总账残差为−0.003348（显式−0.003010），目标收缩值9.634756；残差保留，未重新分摊消除。

实际 profile 发现三次本扩展内核，默认 FA 对照发现真实前后向内核。profile 中还含包装和结果诊断内核，不能把三次称为全部 GPU 调用。二进制 SHA、源文件、原始输出数组哈希和独立验证器均已保存。

## 失败与预算不删除

原捕获运行在“与旧 P1 向量逐位相同”的冻结检查处失败。向量相对差0.0182%，310个元素变化、0个符号翻转，模型端点分数及实际层重放输出完全一致。移除观察回调后源码算术结构相同，但差异原因仍未确定；分配、编译或预热只能作为待查假设。原检查保留失败，未静默放宽。这次失败发生在有限内核执行前。

因此后续另立协议，在已捕获并校验哈希的真实操作数上进行独立局部比较，没有重跑模型或把原失败改成通过。首次局部打包因遗漏 `signed_secant_rules` 失败，亦已保留；修正只补齐依赖。

实际总预算：原捕获1次B2根前向、36次B2层重放、36次辅助B2原FA调用、1次手工有限传播；局部测试4次显式P1、5次有限扩展（15次扩展内核）、5次原FA前向及5次注意力反向，0次模型反向、0次质量评估前向。失败打包另有1次未进入计算的显式调用尝试。

用户最新精度判断：FA 常用混合精度一般可接受，重点排查实现错误。后续将这一精度策略作为正常开发标准；非逐位相同、小值舍入及当前局部0.03%—0.04%误差本身不阻止接入，也不追求恢复旧FP32逐位结果。验证重点为有限公式、端点数据流、mask/尾块、GQA与整网原指标；精度策略可接受不替代这些实现检查。捕获0.018%差异不作为继续开发的硬阻塞，历史逐位检查失败和未确定原因保留。

## 下一步

1. 将该算子接入原 P1，保留真实默认 FA 捕获；消除生产路径中的显式概率、有限矩阵和仅供审计的 N×N 临时量。原显式路径只作开发对照，不能自动回退后隐藏成本。
2. 用原 NI0/NI2/MH0 检查整条归因向量、符号/排序、残差、完整成本和实际内核；继续定位捕获差异。数值非逐位不自动判失败，但变化必须解释和量化。
3. 在原 FlashTrace 输入上检查更长 N 和多样本 B 的实际峰值/吞吐，再按原 RISE/MAS/needle 评估。当前只验证B1N601单层；不外推批量、长输入或整网质量结论。

研究目标仍未完成。主线是保留强 P1 的数学规则并降低其平方级存储，进一步效率优化服从真实来源与原基准。
