# 停止 FT 改造并纠正对照身份

用户纠正后，停止 FT 内容分配改造与 Both 控制器移植。此前确实把“让基线满足 FA/FLA、批处理和低显存要求”扩大成了修改基线方法；在没有完整原版配对运行的情况下，这不能作为可信官方对照。

## 已经改了什么

- `qwen35_ft_native_content.py` 自定义了 FA/FLA value 伴随、输出门控/归一化增益、卷积前来源分配及批量聚合。这是本项目 FT 衍生变体，不能因调用真实官方内核就称为官方 FT。
- 已执行的 core0—3 和全轨迹诊断消费上述自定义内容分配。保留其向量、指标和失败记录，但撤销其作为完整官方 FT 基线的资格。
- 未执行的 `author_both_control.py` 用 AST 提取控制块，去掉原捕获/参数构造，并替换聚合入口。原计划的同步重放使用相同自定义聚合结果，只能检查调度，不能验证完整原版与改造等价。此草稿已经撤出运行目录。

第三方固定源码副本与实际执行路径是两件事。保留原版源码、验证源码哈希以及观察到真实 FA/FLA backward，都不能证明组合后的归因方法就是原版。这里不能再以“没有重写模型或内核”回避用户关于影子实现的实质要求。

## 撤回哪些结论

当前低恢复率说明当时交付的 DT 与自定义 FT 适配均未通过预期的证据恢复验收；不能用弱适配对照得出 DT 胜负，更不能把自定义变体的低分归给官方 FT。

DT 同端点目标回归的 1/40 → 16/40 保留为单例实测。自定义 FT 的 2/40 → 8/40 保留为该变体的目标诊断。两者不构成对完整官方 FT 的比较。

源码中的结构差异与局部重构检查是诊断线索。它们既没有证明完整官方方法的质量有问题，也没有证明本项目改造保留了原方法。旧报告中“修正后的 FT”“可信基线的必要准备”和“继续补齐官方 Both”等表述，均不能作为继续改造或授予官方身份的依据。
