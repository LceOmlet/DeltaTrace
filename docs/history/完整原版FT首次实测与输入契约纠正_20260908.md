**完整、未修改的当前官方 FT 已在 Qwen3.5-9B 的 NI0 上运行：0跳恢复4/40，1—3跳均恢复6/40。** 这次使用完整作者包与控制器。此前自定义内容分配、core控制器和撤回的AST草稿均未参与。

## 实际原版结果

| 原版结果 | needle恢复率 |
| --- | ---: |
| 0跳 | 10%，4/40 |
| 1跳 | 15%，6/40 |
| 2跳 | 15%，6/40 |
| 3跳 | 15%，6/40 |

这是一次完整 `FlashTrace.trace(hops=3)` 调用；0—3跳向量由作者原样返回的 observation base 和各跳增量逐次相加得到，没有重写权重递推。最后一个累计向量与公开API返回分数一致。四个向量保存后，直接调用作者 `evaluate_attr_recovery_skip_tokens`；其函数AST与旧075e7e4原指标一致。保持原整句needle、310个eligible token、40个eligible gold和前10%（31个token）。四次截止分数均无并列歧义。

这是历史开发样本上的单例原版参考，不是独立确认，也不能据此概括整个数据集或证明作者方法数学上正确。

## 原版身份和实际执行

固定官方提交为 `e81b3be50a48dcfc652fbf1b530069b552736e66`。全部16个包内Python文件按官方Git树blob逐个核对，运行前后SHA256一致；完整副本已保存至仓库的第三方目录。运行直接导入原包，没有AST执行、函数替换、自定义FT内容算子或控制器。

实际记录到一次作者Both调用、一次完整模型前向、8个模型原生eager注意力层、24次作者GDN输入准备和4次作者聚合。FLA共调用72次：48次value形状为 `[1,588,32,128]`，24次作者单位值探测为 `[1,588,32,588]`。这包含24个原模型GDN层、24次作者GDN重放和24次探测。没有调用本项目FT value伴随。

原版要求B1/eager注意力矩阵，并物化平方阶混合矩阵。这些是其实际实现和成本，未替换成FA或隐藏到缓存。FLA仍为既有隔离环境的真实安装版本，保留此前已记录的设备映射、调度和上游WY修复；本轮没有修改模型、FA、FLA或FT源码。真实原生调用不等于对任意长度的正确性或性能保证。

## 输入差异是本轮纠正的关键

| 输入准备方式 | prompt长度 | 固定响应含EOS | 总长度 |
| --- | ---: | ---: | ---: |
| 旧075e7e4原实验包装，旧DT使用 | 357 | 248 | 605 |
| 当前公开API，显式开启chat template | 350 | 248 | 598 |
| 当前作者exp2构造器默认值 | 340 | 248 | 588 |

旧版添加前导空格、`Context/Query` 包装，并设置 `enable_thinking=False`。当前exp2创建Both时没有开启 `use_chat_template`；当前类默认值为False，直接使用缓存prompt文本。公开API和作者Both类的默认值一致。

第一次驱动错误地设置 `use_chat_template=True`，并以为能得到旧605-token输入。输入检查实测得到598，已在模型body执行前停止。这是驱动配置错误，不能写成官方FT运行失败或算法失败。保留原失败协议、源码、26.72秒耗时和一次实际模型加载。

随后只做CPU tokenizer核对：旧605和首次598的哈希均被重现；当前作者默认588被事前冻结。这例当前340个user token中，除第一个token外与旧前导空格版本相同；gold和eligible位置列表分别完整一致。第二次直接使用当前作者默认值，实际传入模型的588-token哈希通过核对。没有修改FT或tokenizer模板来制造旧输入。

**旧DT的16/40仍是605-token输入结果，不能与本次588-token原版FT的6/40直接判胜负。** 以前的自定义FT成绩也不会因原版现在能运行而重新取得官方基线资格。

## 成本和保存

成功任务共62.77秒（打包之前），其中完整模型加载18.35秒、完整三跳归因30.73秒。归因计时包含原始前向、作者重放/探测/聚合、冷调用、被动hook及Python调用观察；不能称为去除诊断后的稳态速度。完整模型驻留时，记录峰值allocated为21,600,765,952字节，reserved为21,793,603,584字节。

此前完整导入依次缺少官方声明的wordfreq和spaCy。本轮用独立依赖目录安装，保留解析和安装记录；未用假模块或AST提取绕过导入。两阶段依赖准备分别144.62秒、45.44秒。全部任务合计两次完整模型加载（含驱动停止），一次完成模型前向，零生成、零删除曲线、四次原needle调用。四个进程均已核对终止。

归因向量、源文件、冻结协议、异常、调用形状及终止收据已下载并核验。完整常驻原版FT与旧流式缓存DT的耗时不能直接当作公平速度比。
