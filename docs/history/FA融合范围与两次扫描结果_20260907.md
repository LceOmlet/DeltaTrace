# FA 融合范围与两次扫描结果

FA 主干的分块有限传播已经可用，但不能把“仍有融合空间”直接解释为“整网还能明显提速”。本轮减少一次平方阶扫描的候选通过了局部数值核验，却比当前版本慢约30.5%，按冻结规则未扩跑整网。当前默认研究路径继续使用共享端点均值的三次扫描版。

| 部分 | 是否应使用 FA 框架 | 当前情况与收益边界 |
|---|---|---|
| 两端点 QK、有限 softmax 权重、UV0、中心化系数、Q/K/V 乘法传播 | 是；这些会生成 token×token 中间量 | 已用 FA 分块避免全局平方矩阵；重复分数计算仍存在 |
| Q/K 端点平均、缩放、块内系数转换 | 适合随加载与计算融合 | 端点平均已经复用原共享缓冲，未新增全局均值矩阵 |
| 输入布局复制 | 可由 FA 步长寻址接替 | 上轮候选每层准备7→1内核，但原B4约慢1.5%，未默认采用 |
| Q 与 K/V 两条传播的重复分数计算 | 匹配 FA 反向的转置和累加框架 | 本轮两次扫描候选局部正确，但局部约慢30.5%，未整网集成 |
| 公开 LSE 获取 | 首先是接口复用问题 | 当前仍每层额外调用一次默认 FA；当前 Transformers 丢弃 return_attn_probs 请求，不能直接删调用 |
| U 转换、输出三次 FP32 转换 | 可以扩展已有编译边界 | 当前仍在边界外；预期收益小，不能根据少几个内核就承诺提速 |
| RoPE、GQA 输出归并 | 无须塞入 FA 主内核 | 已经使用公开编译融合；是否进一步融合由实测决定 |
| 线性投影、MLP、RMSNorm、残差与目标分数 | 不要求 FA 融合 | 应复用矩阵乘法库、原生算子与已有编译器；本轮未开展这些优化 |

两次扫描候选保留同一有限分配：`ΔP·V0 + P1·ΔV`。设 `T=U V0ᵀ`，`L` 是原有限 softmax 的对数均值，`c=Σ(L·T)/ΣL`，块内系数仍先中心化为 `C=L⊙(T−c)` 再转 FP16。Q/K 端点平均和输出量化顺序保留。

原实现分别扫描一次计算中心项、一次计算 Q 乘子、一次计算 K/V 乘子。本轮在 K/V 扫描中同时计算转置系数对 Q 的贡献，复用厂商 FA 的共享转置布局、FP32 原子累加工作区和未修改的32×32转换例程。这样从3次平方阶扫描变为2次，加一次线性转换；内核启动总数仍为3，不应宣称“内核调用少了三分之一”。每组完整因果块的矩阵乘法从12次变为9次，减少的是该部分乘法工作25%，不是墙钟时间25%。另增加线性 FP32 累加空间及2KiB共享系数块。

这次接入保留了全部错误记录：

1. 第一次编译引入完整 FA 参数头，缺少 ATen 生成器头文件。随后只建立显式参数载体，调用原泛型转换函数；未修改厂商源码。
2. 第一次局部测试误用了通用转换路径，Q 相对误差1.393，其余输出相同，预热配对后立即停止。
3. 按厂商32×32分派改用专门转换后仍失败，Q相对误差1.410。原因还包括：原子累加写入的是逻辑坐标，原转换要求的是厂商内部寄存器排列。不能把二者混用。
4. 将厂商累加复制布局与其转换例程成对接入后，通过原误差门槛。没有放宽容差，没有事后重排输出分数，没有将大误差解释成正常 FA 精度。

最终只在此前捕获的真实 NI0 第35层做了局部比较，B1、32个Q头、8个KV头、N=601、D=128。三次配对中，Q最大绝对差为3.8147e−6、最大相对L2误差约1.214e−6，Q符号翻转0；K、V、归一化和中心项全部相同。原子累加结果有极小的重复间差异，原始数组哈希和逐项误差保留。这里只证明该局部数值范围，不证明整网符号或质量。

|---|---:|---:|---:|
| 当前共享均值三次扫描 | 1.8695ms | 1.8690ms | 1.8693ms |

两次扫描中位数高30.49%，两组配对都慢。协议事前规定，局部中位数比值大于1.05即不进入整网，故本轮没有整网归因、FT归因、生成或RISE/MAS查询。少做的乘法没有抵消新增执行成本；原子写入、转置与寄存器压力是需要分解的候选原因，目前没有独立剖析证明各自占比。

局部增量峰值分配从29,694,976字节升到39,656,448字节，差额9,961,472字节恰为本例的线性FP32累加缓冲。这不是整网峰值测量，显存也未作为固定否决线；未扩测的原因是实际速度。本轮局部检查不改变早期捕获任务曾未通过整网相同性门槛的历史记录。

本轮共4次编译尝试（其中1次依赖失败，耗时合计约166.01秒），10次局部算子调用（两次失败各2次，修正后6次），0次整网或质量调用。每次局部调用均包含3个有限/转换内核；CPU数值核验和搬运另在原记录中保留。没有为失败实现跑整网或参数扫描。

公开 LSE 接口核查使用实际安装的 Transformers 源码 SHA256 `293fe81c6bd38aac8a3bc6ae086ff21b9695b349e97c9650b1fe61e42a36d710`，在CPU执行原参数处理函数，确认请求开启前后的传给FA参数字典相同。这个结论只针对当前适配器，不代表所有版本或接口都不能返回LSE。

后续保持 FA 优先：已验证的两次扫描代码保留为局部原型，当前三次扫描路径继续使用。下一次内核改动应先审查厂商完整反向调度中分块、共享存储、寄存器和累加策略的配套关系，避免继续只按少乘法或少内核预测速度；在能说明预期成本变化后再做小预算验证。LSE接口受限和转换边界仍记为未完成，不据此改写模型或恢复显式平方矩阵。MLP/输出头继续后移。

当前还没有可据此承诺的明显整网提速，更没有新的FT质量或成本胜出结论。独立确认、条件删除方向以及整体质量—成本目标仍未完成。
