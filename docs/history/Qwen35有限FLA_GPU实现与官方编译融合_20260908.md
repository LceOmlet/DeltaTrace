# Qwen3.5 有限 FLA：GPU 实现与官方编译融合

2026-09-08。已实现真实双端点上的 GPU 混合有限 pullback，并用 PyTorch/Inductor 融合其布局、类型转换及逐元素开销。支持本次两个真实样本、32头、129-token前缀的批量计算，继续使用原生 FLA 伴随算子和厂商 BF16 GEMM。该局部进展不等于整网支持或胜过 FlashTrace。

## 实际复用与复杂度

[GPU实现](../../research/runtime/finite_fla_gpu.py)直接调用原生 `chunk_bwd_dv_local` 与 `chunk_gated_delta_rule_bwd_dhu`。局部收缩使用已有 `torch.bmm(..., out_dtype=torch.float32)`，输入为BF16；唯一手写的新Triton操作是既定有限衰减项的加权前缀扫描，使用编译器 `tl.associative_scan`。没有重写注意力或模型forward，也没有替换原生普通backward。

同时批量处理样本、头和64-token块，末块通过零q/k/v/beta/do、零raw-g及延续累计g补齐，以保持虚拟补齐区的恒等状态转移。该补齐仅用于局部计算，不冒称已验证真实异长模型padding的完整有限传播。无需全局T×T矩阵或全序列逐token K×V状态；实际常数、端点状态存储和长序列成本仍需整网验证。

官方 `torch.compile(fullgraph=True, dynamic=False)` 形成一个图、没有graph break；生成代码和实际profile显示厂商GEMM、编译器生成的融合内核及原生FLA反向状态内核，生成源码19个文件均保存并校验。模型/FLA的2853个源码文件执行前后再次核对，只含以前已公开的三处适配，没有新增后端修改。

## 冷启动与全部调用

编译版首次调用25.746秒，包含原生算子准备和编译；不是纯编译计时，也不是稳态延迟。虽然设置了 `max_autotune=False` 和禁用CUDA图，实际Inductor仍记录51次 `benchmark_gpu` 调用，这是编译器默认内核调优，内部重复数没有独立采集，不能称“零调优调用”。已纠正当前runtime注释；执行快照保留原样。形式参数设置不替代实际调用证据。

两任务总计：16次混合系数求值，其中15次完整局部有限pullback包含两段原生伴随；9次原生归一化后普通backward helper作为同负载成本对照。所有第一次准备、三轮配对、独立profile都计入上述次数。原生算子自身调优和编译器内部基准另行说明，不将API次数冒充GPU内核次数。两任务job时间约27.36/41.71秒，不含产物压缩与下载。零模型加载、零新模型前向、零生成、零原指标评测和零整网归因。

局部CPU分析器首次遗漏结果列表的return，补上后重新分析已保存数组；未重跑GPU。两个GPU任务均成功且已结束。压缩包分别约30.87/30.91MB，下载并通过CRC；激活/系数NPZ在本机与远端保留，完整profile留远端，公共仓库发布派生结果与哈希，不发布原始模型激活。
