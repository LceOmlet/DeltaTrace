# Qwen3.5-9B 权重与 FLA 真实导入

找到远端已有的 Qwen3.5-9B，完成官方来源核对并打通隔离环境的真实 FLA 导入。尚未运行该模型的 GPU 前向、归因、评测或真实批处理，不能称为完整模型支持。

权重来自 [Qwen 官方固定版本](https://huggingface.co/Qwen/Qwen3.5-9B/tree/c202236235762e1c871ad0ccb60c8ee5ba337b9a)。共享目录中的四个完整分片逐文件 SHA-256 均与此版本的 Hub LFS 记录一致，共19,306,310,880字节；只读流式校验约98.31秒，没有下载或修改权重。config 和权重索引也与固定官方文件逐字节相同。索引与775个张量头部及分片边界核对通过；tokenizer 文件已记录本地哈希，尚未逐文件与官方版本核对。

实际文本配置是32层，其中24层线性注意力、8层全注意力；默认BF16，全注意力head_dim为256，线性Q/K与V头维度为128，EOS为248044。当前Qwen3-8B有限FA扩展固定head_dim128、FP16，不能直接拿来运行这个模型。新模型还需要状态更新/门控相关的有限传播规则、实际捕获与批处理；这些未完成。

原作者缓存轨迹可用于固定文本目标，但不能把旧模型的token ID直接输入新词表。后续应使用作者缓存文本和新tokenizer重新编码，核对目标区间、可归因范围、EOS基线与原评测映射；不得静默生成替代答案，不把新模型测试冒称原论文表格复现。

已有环境为Torch2.8.0+MetaX、Triton3.0.0+MetaX、Transformers4.57.3，无FLA。共享目录里的Transformers5.13.0、FLA0.4.1/0.5.1及对应fla-core wheel已与PyPI官方发布哈希比较一致。选择FLA0.4.1做首次兼容检查，因为0.5.1 CUDA额外依赖声明Triton>=3.3；这不意味着0.4.1保证兼容Triton3.0，实际导入仍提示推荐至少3.2。没有替换厂商Torch/Triton。

在独立venv中复用厂商运行时并安装固定包后，第一次真实导入失败。原因是FLA识别Triton后端为`maca`，却访问不存在的`torch.maca`，而厂商Torch使用`torch.cuda`接口。0.5.1的设备模块也保留此映射缺口，没有为同一已知原因再安装测试0.5.1。包安装成功不等于环境整体依赖检查通过：继承的vLLM/sglang等无关软件存在版本冲突提示；本次没有使用这些软件。

新增明确、可审查的设备名称适配器 `research/runtime/fla_maca_device_mapping.py`，只允许修改指定虚拟环境中哈希固定的FLA0.4.1 `utils.py`：

1. 设备映射增加`maca → cuda`，与厂商Torch设备接口一致。
2. `device`使用该映射函数。

没有创建`torch.maca`别名，没有把Triton后端改成cuda；`device_platform`仍为maca，`IS_NVIDIA`仍为false。适配前后逐文件核对2853个FLA/Transformers Python文件，唯一差异是上述两行。源文件哈希由`03e3e41a62741d45913a2d2d35de630aaba13dcbb0fb1e8c1f7904446a688cf1`变为`2971d3805da9da36e1000e82c0abddb491d65eec27c393e1431921281f09b2a6`。不是原封不动的FLA安装，适配范围必须随结果披露；没有改模型公式、状态递推、内核、前后向或原厂精度。

适配后的真实导入通过：Qwen3.5模块的chunk/recurrent函数与FLA导出的函数对象一致，fast-path依赖可用，设备身份核验通过。chunk入口含PyTorch Dynamo装饰器，直接`inspect.getsourcefile`落在Dynamo文件中；函数对象一致和包源码核对并不等于GPU运行证明。后续必须从实际调用和内核执行确认FLA分派，不能只用此导入结果宣称FLA已加速模型。

执行成本：权重只读校验约98.31秒；建venv约2.12秒、安装约8.53秒、失败导入约16.75秒、映射后导入约31.55秒。没有模型加载、前向、归因或质量查询。源码检查、元数据读取及一般CPU开销未包括在上述分项时间中；导入可能初始化设备运行时，未做GPU profiler，不能从零模型调用推断完全没有底层GPU活动。

下一步保持FA成本审查和原强方法目标：没有新证据宣布FA收益耗尽。Qwen3.5前置兼容问题已缩小到实际FLA算子运行、head_dim256/BF16注意力路径、固定文本重编码及有限传播支持。下一次GPU验证先冻结小预算，使用原缓存输入核对真实模型执行与批处理；先失败即停止，不铺开质量曲线。完整归因、相同模型FT对照、独立质量与符号结论均未完成。
