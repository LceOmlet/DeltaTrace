# source-v2 GPU 配对重跑协议

冻结于首次 GPU 调用之前。目的：区分“测法范围及预算一致”与“新 reference 提升了证据排序”，补充实际模型执行证据。

## 固定范围和条件

- 模型：原 Qwen3-8B，原权重回执、原作者代码、27 项冻结方法依赖及有限 FA 库均校验。完整原输入、固定完整响应加 EOS 不变，不重新生成响应。
- 正式范围：NI 6、VT 4、HotpotQA 1，全部 1,048 例。先执行 NI MQ-Q2、VT H4-C1、HotpotQA 第 0 例，仅检查运行能否完成，不用于选择任务、参数或结论。
- 每例重新执行两次 DT：旧的全 prompt 候选 reference，以及新的正文候选 reference。两次归因使用相同模型、方法、目标与正值评分视图。
- 两份 DT 归因均在同一正文候选集、同一 token 预算及同一删除路径定义下评分。因此，两者差值只隔离 reference 改变的作用。
- 同例实际运行原 FT K=1、K=3，输入身份必须与 DT 相同。K1 计算正文删除忠实度与 recovery，K3 计算 recovery，不替换为旧论文均值。
- Token recovery 预算固定 5%、10%、20%、30%、50%，并列按 prompt token 位置升序。句子/行级指标作为独立次要指标，预算单位及实际 token 成本单独报告。
- 每个删除输入只允许改正文候选位置，完整目标不变。所有方法的最终删除输入必须相同，且等于新 DT reference。旧 DT 的归因 reference 本来不同，它的删除指标仍使用共同正文路径，不能将二者混称为同一 reference。

## 判断是否有用

主比较为新 DT 与旧 reference DT 在相同正文预算下的 Recall@10% 配对差；同时报告各预算 recall/precision、上限归一化 recovery，以及共同正文删除下的 RISE、MAS。RISE/MAS 越低越好，recovery 越高越好。

逐任务报告均值、配对差与 95% 配对 bootstrap 区间（10,000 次，固定 seed=73）。另外分别报告 NI、VT、HotpotQA 和全部 11 任务等任务权重均值；分组重采样在每个任务内部进行，保持任务权重不变。预算间的相关性通过按整条样本重采样保留。多个次要列的区间仅作描述，不以其中最好的一列认定成功。

“改得有用”的证据应是：在相同评分对象和预算下，新 reference 改善证据恢复，并得到共同删除指标支持；报告改善覆盖哪些任务、是否存在退步。若区间跨零则结果不确定，若仅缩小候选集后旧分数变化、而新旧 reference 配对没有改善，则只能支持范围修正，不能声称归因质量已改善。原指标与新指标的数值不作直接提升比较，也不要求结果必须支持修复。

同时比较新 DT 与本次 live FT K3 的 recovery、FT K1 的忠实度，保留所有任务的正负差值。保存每例有符号向量、输入身份、两个 reference 的哈希、实际删除输入、原始曲线、运行耗时与峰值显存。

## 执行与失败处理

每个完整任务单独运行，使用独立结果目录。控制器仅复用哈希、协议、范围及配对审计标记都匹配的完整结果。失败任务保留原输出，停止队列，不静默跳过或更换方法；修正执行故障后从完整任务边界继续。

本文件记录实验设计，不表示 GPU 已启动或完成。执行状态和结果以实际回执为准。
