# Qwen3.5 NIAH RISE：逐例诊断与改进方向

2026-09-13。分析已完成的 600 个 NIAH 样本、原始归因向量和删除曲线；本次没有新模型调用，没有修改论文数字或方法。

最有证据支持的解释是：DT 与 FT 对证据正文和问题文本的排序不同，而当前 RISE 衡量删除后整个固定回答的得分。已有数据足以定位这种分离，但不能据此断言问题文本的删除解释了全部差距，更不能断言 GDN 实现错误。

## 差距范围

RISE 越低越好。FT 使用论文规定的 K=1；DT 使用有符号排序。每行 100 例。

| 任务 | FT RISE | DT RISE | DT−FT | FT 更好的样本数 |
|---|---:|---:|---:|---:|
| MQ-Q2 | 0.09823 | 0.11486 | +0.01663 | 86 |
| MQ-Q4 | 0.14141 | 0.17448 | +0.03306 | 95 |
| MQ-Q8 | 0.37039 | 0.37524 | +0.00485 | 60 |
| MV-V2 | 0.09737 | 0.09226 | −0.00511 | 33 |
| MV-V4 | 0.12844 | 0.13605 | +0.00761 | 60 |
| MV-V8 | 0.25076 | 0.23748 | −0.01328 | 41 |

MQ-Q2、MQ-Q4 的逐例差值中位数分别为 0.01513、0.03040；双侧各去掉 10 个样本后的均值仍为 0.01640、0.03231。不是少数极端值造成的。配对样本 bootstrap 的 95% 区间分别为 [0.01311, 0.02015]、[0.02902, 0.03735]，属于探索性区间，未做六任务多重比较校正。

## 可直接观察到的机制线索

MQ-Q4 在第 4/20 个删除步骤（约 20% 的可删除 token；分组取整可能略超 20%）的任务均值：

| 观察量 | DT | FT K=1 |
|---|---:|---:|
| 已删除的标注证据 token 比例 | 70.09% | 64.19% |
| 已删除的问题及答案前缀 token 比例 | 60.30% | 84.67% |
| 归一化回答得分，越低代表破坏越强 | 0.33196 | 0.22204 |

这里的“问题及答案前缀”是 prompt 最后以 `What ...` 开始的检索请求及随后已有的回答前缀，含键名及模板词，不应解读为纯粹的格式 token。分段使用完整实际输入的 token 字节边界，600 例解码后的 prompt 和 target 与固定源文件逐字节相等，六个数据文件的 SHA256 与运行记录一致。

MQ-Q2 也出现相同方向：DT/FT 的证据删除比例为 84.96%/71.80%，问题及前缀删除比例为 70.24%/88.87%，回答得分为 0.19818/0.10288。MQ-Q4 的 AUC 差距约 87.3% 来自 10%–50% 删除区间；MQ-Q2 的约 79.9% 来自 10%–25% 区间。

因此，DT 找到更多标注证据，不保证同一删除预算下对整段回答的破坏更强。FT 更早删除问题文本，是当前数据支持的一条解释线索。所有方法使用相同删除范围和评分目标，这一现象本身不构成测试不公平，也不能直接证明 FT 在利用无关 token。

当前目标是完整固定回答加 EOS，含较长解释和最终答案；MQ-Q2/Q4/Q8 的平均目标长度为 290/408/697 个 token。固定回答在评分时以 teacher forcing 提供，回答内部已经出现过的信息仍在后续位置可见。其对差距的具体贡献尚未通过分输出评分验证。任务内部“回答长度与 DT−FT”的相关系数很小（Q2 0.047、Q4 −0.058、Q8 0.009），不能把“越长越差”写成已证实结论。

## 已检查但不支持作为首要原因的项

- 有符号排序：MQ-Q2/Q4 的有符号 RISE 减正分 RISE 均值仅为 +0.000058/+0.000062；两任务前 20% 删除中没有负分 token。截负不能解决主要差距。MQ-Q8 有符号排序反而比截负改善约 0.00193。
- 数值或回放失败：600 例保存的层回放相对 L2 均为 0；所有方法的评分起止端点一致；600 例原始完整得分均大于全删除得分。Q2/Q4 总量守恒相对残差绝对值的中位数约 0.149%/0.133%，且与逐例 RISE 差距的相关性弱。这些检查降低了明显回放错误的可能性，但不能证明每个 token 的归因准确。
- 全局缩放：RISE 由排序及删除后的原生模型得分决定。给分数乘正的常数不会改变排序，因此修总和或做正比例归一化不能改善这一指标。

## 建议的最小验证顺序

1. **先检验问题文本是否解释差距。** 保留当前结果作为原口径，增加一个两方法完全相同的对照：问题及答案前缀固定，只删除正文。DT 参考也只替换正文，评分仍用原来的完整固定回答，并重新计算两个端点。不能从现有曲线直接重算这项对照，因为实际输入和 DT 参考都变了。如果差距明显缩小，再用正文和问题的分组删除验证二者的交互；如果不缩小，继续查证据内部 token 排序。
2. **要提升原口径，优先研究内容/控制交互的分配。** 当前 attention、GDN 和输出门采用 content1 分配。对乘积 `c*g`，当前规则是 `g1*Δc+c0*Δg`；对称规则是 `(g0+g1)/2*Δc+(c0+c1)/2*Δg`。两者理论上都保留端点差值，但 token 排序可以不同。可先在 GDN 输出门使用统一对称规则做一项消融，然后单独考察 attention 的对应规则。每项固定其他规则，不按任务或样本挑层。现有代码支持 GDN 输出门的对称候选，但尚未在本次 600 例上运行；不能保证提高 RISE。若改变共享算子规则，应按论文原则同时检查 Qwen3。它是待验证的新变体，不是已确认的实现修复。
3. **单独检查长回答的作用。** 用预先定义的最终答案目标，配套计算归因与删除评分，两方法一致，并与完整目标对照。这能检验解释目标是否影响结论，但属于不同目标，不能用它替换原 RISE 来宣称原指标提高。仅将全回答拆开求归因后再按原权重求和，在相同线性反传下不会自动改变总归因。

规则选择需要新的开发样本；当前 600 例已用于诊断，不能再声称是完全未见的选择外测试集。先冻结一个候选，再在新的验证样本及所有任务上检查 RISE、MAS 和 Recall，防止只改善 MQ 的 RISE 却损害已体现的证据定位能力。

Qwen3.5-9B 确实包含 24 个 Gated DeltaNet 层和 8 个全注意力层，可见 [官方模型卡](https://huggingface.co/Qwen/Qwen3.5-9B)。架构事实只提供消融的对象，不是本次性能差距的因果证据。
