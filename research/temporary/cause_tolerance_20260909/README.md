相同NI8/MH8的干净有符号RISE显示：最明确的待解释问题是NI的DT相对FT优势反转。两模型MAS都优于各自FT，MH的RISE也都优于FT；不能先验归纳为Qwen3.5所有方面失败。

[初始核验](initial_evidence.json)重新核对3份原报告、向量文件、全部32条输入及向量身份，未运行新模型或指标。[逐例数据](baseline_cases.csv)和[均值](baseline_means.csv)显示：NI的DT−FT RISE由Qwen3的−0.011089变为Qwen3.5的+0.017283；逐例领先数量从7/8变为1/8。这定位了待解释现象，尚不能把架构差异与实现、精度和模型行为分离。

历史对照中的FT needle使用K=3；原论文CSV的配套轨迹为n1。这里保持原开发对照身份，不替换或混合这两组数值。32例有符号视图由已验证原曲线及有证明的复用组装，不能宣称重新运行32例。

本轮第一项算子核对直接调用当前原生FLA前向和冻结`finite_fla_pullback`，检查纯保留路径中的连续门顺序分配，并覆盖跨64-token分块边界。四种固定算子情形只用于核对数学机制，不是新质量基准，不测RISE/MAS，不改任何框架。对称门的真实删除作用、有限分配及舍入余项分别记录；即使反例成立，也不能据此认定它解释了真实NI差距。

计算预算：长度4和67，各检查0.1→0.9及反向两种门变化；每种情形一次原生双端点前向、一次原生删除组合前向及一次冻结有限FLA（内含两项原生伴随）。共8次局部前向、4次有限调用，无模型加载、无答案生成或指标评分。

## 真实16例：顺序门假说尚不足以解释NI差距

[汇总与逐例核对](qwen35_real_gates/summary.json)、[384层原始统计](qwen35_real_gates/results.json)、[分支向量](qwen35_real_gates/vectors.npz)已完成。17次根前向包括1次原生初始化和16次DT；没有评分或生成。输入身份、全部层和向量哈希均核对。

诊断事件预先定义为：某个窗口在原输入下的标量保留率至少`exp(-1)`，EOS基线保留率却低至少10倍。它测条件是否出现，不测真实删除效果。

| 窗口 | NI：占原输入仍保留窗口的比例 | MH：同一比例 |
|---|---:|---:|
| 16 token | 2.18% | 2.57% |
| 64 token | 4.80% | 5.62% |
| 128 token | 7.08% | 7.12% |

因此，算子反例的相关条件会在真实任务出现，但在NI/MH中频率接近，部分尺度反而MH更多；不能直接把它升格为NI特有差距的主因。这不是对该机制的彻底排除——它可能落在不同的重要证据位置——但在追到真实删除集合前，没有依据做全网门修补。中间分支池的g绝对质量约占NI7.1%、MH6.4%；该池跨层重复计算，不能说遗忘门解释了最终输出的这些百分比。

另记录一项数值混杂：本次MH8的完整DT向量及原生根效应与旧恢复运行完全相同；NI8相对更早运行的向量L2相差1.50%–2.66%，原生根效应也已不同。尚未确定这种跨运行差异的来源，不把它当作observer导致的方法变化，也不把历史指标赋给新向量。后续质量候选必须同次比较，先分开原生端点差异与有限传播规则差异；不因这些微差改写官方框架。

## 第二轮：完整调用中的同步开销可修复

[Qwen3原始剖析](profile_qwen3/results.json)和[Qwen3.5原始剖析](profile_qwen35/results.json)各覆盖NI0/MH0一次预热及一次剖析，完整向量与同次预热相同。Qwen3每例877次`mcStreamSynchronize`，自身CPU耗时约186/286ms；Qwen3.5每例158次`mcDeviceSynchronize`，约190/342ms。这指出DT控制代码频繁等待GPU，是可以修复的执行开销。Profiler总时间含采集开销，包含时间会重叠，不能把事件时间简单相加当作运行占比。

Qwen3使用官方编译器执行原有设备端校验，一次归因仍检查828项谓词和36项最大值，在API返回前统一取回结果；有效输入通过，注入NaN仍报错。Qwen3.5保留32层有限性检查和所有诊断，阶段计时换为原生事件，取消每阶段前后的设备屏障。两者不改变有限公式、模型前向、原生FA/FLA、精度或目标。

|---|---:|---:|---:|---:|
| Qwen3，NI8/MH8，样本B1/端点B2 | 10.9598s | 10.3112s | 5.92% | 18.760811→18.761346 |
| Qwen3.5，原任务内8组B2/端点B4 | 12.5546s | 11.5732s | 7.82% | 23.628107→23.628037 |

[Qwen3逐例/汇总](qwen3_deferred16/summary.json)、[Qwen3.5逐组/汇总](qwen35_deferred16/summary.json)由[核验程序](verify_deferred_results.py)从原始结果、向量和源码重新核对。两模型分别96份完整向量全部相同，因此有符号RISE排序及正值MAS/needle输入相同；没有重新评分或声称质量提升。Qwen3共96次完整DT；Qwen3.5共48次B2调用、96个样本向量。每种形状先预热，随后两轮交错测量；Qwen3.5所有测量调用均无新增Dynamo图。首次调用与热调用分别保留。

长NI的收益更小：Qwen3部分样本不足2%，Qwen3.5最长三组约3.3%–4.1%。因此下一项效率工作应看长序列原生重放和有限传播中的矩阵计算，以及Qwen3真实样本批处理，不能继续把辅助LSE或几个小统计当作主要大头。

## 第二轮：FT目标聚合差异与被否定的目标修法

[只读源码核验](ft_seed_scope_audit.json)通过[AST检查脚本](audit_ft_seed_scope.py)复验。原论文Qwen3 FT首轮聚合范围为CoT+答案，固定Qwen3.5 FT扩展首轮范围为答案；二者递归轮再覆盖CoT+答案。因此`output_span`参数本身不能证明两版FT首轮目标相同。FT源码、哈希及调用都保持固定。

这只是比较中的明确差异，尚不能证明它造成了NI的优势反转。为检验最简单的DT目标替换，[预定NI0/1、MH0/1四例](diagnose_qwen35_target_scope.py)固定所有有限规则，只比较整段生成+EOS与作者原方法重新定位的答案范围。它是目标消融，不是FT注意力加权种子的复刻。作者缓存、输入和生成完全一致，RISE保留负值，MAS/needle用正值视图；8次DT、294次原作者指标根前向，无FT或生成调用。

机制上，答案条件概率是在已经给定作者CoT的条件下计算。NI0/1的仅答案原生端点效应为12.36/6.14，而整段为178.24/186.30；MH0仅答案效应甚至为−1.04，整段为141.06。两种目标测的依赖确实差很多。FT的注意力传播与DT条件概率有限分配也不是同一数量，照搬位置范围不能使二者目标自动相同。本轮未单独干预CoT前缀，不能把上述解释扩张为已证明的整体NI根因。

当前质量结论：没有发现可直接采纳的简明修法。连续门反例存在但未解释NI特异差距；答案范围替换已被实测否定；已失败的归一化修法不重跑。下一步仍需追同次真实早期删除集合的排序错配，保持原指标视图和固定FT，不按例调规则。加速与质量研究分别交付，不把加速通过写成DT已胜出。
